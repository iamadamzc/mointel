## 3. Float (the one capability the desk has never had)

**The state today.** The dossier has slots for a sourced float (`displayedFloat`, `displayedFloatDate`, `displayedFloatSource`, `lib/research/types.ts:507-510`) and they have been empty since version 237, because the research bundle never contains a document that states a float, and only a sourced float is admitted. The only float on the board is the Sheet's.

### Option (a), recommended: the desk's own upper bound, from SEC filings

Designed 2026-09-04 (`docs/threads/research.md`, "HIS QUESTION: every float is invented"; Integration agreed it needs no fixture set), never built:

    float bound = filed shares outstanding  minus  holdings PROVEN to be affiliates

- **Subtract only what is proven:** officers, directors and 10%+ holders from Forms 3/4/5, 13D filers, and any holder at 10% or more whatever form they filed. A 13G holder under 10% stays IN the float.
- **Why that rule:** every affiliate we fail to find makes the number HIGHER, which can only make a name look less tight than it is. The only way to be dangerous is to subtract someone we should not have, and the rule never does. So the true float is at most our number, and the board says so: **"no more than 4.2M shares, from SEC filings as of Sep 14"**. Below his 10M line that is a proof, not an estimate; above it, it says nothing and prints nothing more.
- **Coverage, measured earlier (item 23, 40 issuers):** Forms 3/4/5 exist for 98%, 13D/G for 70%; the limit is the denominator, a filed share count, on 80% (185 of 231). Where there is no share count the cell is UNKNOWN, never a guess.
- **The three ways it can go too LOW, and the guard for each** (all from the same 09-04 work): a share count that is stale under dilution (the age is carried and a stale one reads CANNOT VERIFY, not a number); a holding stated before a split subtracted from a count after it (the split-basis guard is already shipped in the supply pair); one holder counted twice across a Form 4 and a 13D (new: de-duplicate by filer CIK).
- **Source, for Commercial's allow-list:** SEC filings only, by construction; no web search, no vendor page. The stored source names each filing's accession number, so the cell can say "estimated from SEC filings" and every subtracted holding is auditable.
- **What it needs built:** Forms 3/4/5 are not fetched today (`lib/research/sec/forms.ts` lists 13D/13G and Form 144 but not 3/4/5); their XML is structured and parses deterministically. 13D/13G cover pages are the hard half; if that parse proves unreliable the bound falls back to shares outstanding minus Section 16 holders, which is looser but still a true upper bound. **No model call.**
- **Validation before it reaches the board** (pre-registered, no money): on a sample, check every subtracted holding is (1) an affiliate by the rule, (2) on the share count's split basis, (3) not counted twice, against the filing that states it. Commercial's measurement (researched float above filed shares) does not apply: the bound cannot exceed the share count by construction.

### Option (b): a model-researched float, as the Sheet does it

The research model is asked for a float with its source and date. Commercial's conditions all apply: a source allow-list in the prompt (SEC filings, company releases, exchange notices) and an explicit ban on vendor float aggregators (stockanalysis.com bars automated access, standing memory); the stored source must name what was cited; the cell reads "{figure}, estimated from {source}, as of {date}". **Before it shows**, a pre-registered measurement on a sample: how often the researched float exceeds the filed share count of the same date (which a float cannot do), reported as a count beside the label (Commercial section 2 item 1). One mechanical problem: today's discovery search uses a domain BLOCKlist (`lib/research/catalyst/domainPolicy.ts`), and a company's own investor site cannot be put on an ALLOW-list in advance, so "company releases" would mean newswire copies only.

### Option (c): verdict only

The board's float column shows Float Quality (section 5, row 9) and no number. This is the report layer's standing default (Integration 2026-09-17, Commercial section 2).

**Recommendation: (a).** It is the only option that is sourced, free, and wrong only in the safe direction, and it is the shape the desk already ships elsewhere (`supplyBound`). Until (a) is validated, the column shows (c), so nothing unverified prints in between.

**Overhang / Float** (recap prompt, Dirty Float Protocol item 2) is computed in code from the supply ledger's share-denominated blocks divided by the float. Against an UPPER-bound float the ratio is a LOWER bound on the true one, so "at least 2.0x" is proven when it binds and silent otherwise. Same honesty rule, same direction.

## 6. Rules carried into the contract

- **Never fabricate:** every model field has an explicit UNKNOWN; every computed field returns UNKNOWN when an input is missing; no field falls back to a default number.
- **Float is never bare:** the cell is "no more than X, from SEC filings as of D" (option a) or "X, estimated from {source}, as of D" (option b); "Float" alone never prints. The existing float-above-shares-outstanding refusal stays.
- **Grades are readings:** stored A / B / C / AVOID, displayed in Marketing's words, one legend, rubric published. **Legend expiry trigger:** the sentence "not tested against outcomes" is changed in the same commit as the first test of the grades against outcomes.
- **No em dash** in any produced text (the report path already passes every dossier string through `withoutEmDash`, `lib/desk/reports/research.ts`; the board's reader must do the same for the new fields).
